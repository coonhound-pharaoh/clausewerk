## What the migration does

Three rules, modelled on 0025.

- **(a) Write scoping.** The four role-only INSERT policies on `cw.negotiation`,
  `cw.negotiation_round`, `cw.negotiation_position` and `cw.position_movement`
  are DROPped and re-CREATEd by name in the house two-branch shape: Legal
  unconditional, requester gated on ownership. `cw.negotiation` tests
  `cw.owns_agreement(agreement_id)`; round and position test an `exists` against
  the parent negotiation; movement tests an `exists` through position to
  negotiation. Each requester branch states the ownership test in the same words
  as the read policy sitting above it in 0011.
- **(b) Read scoping of the three negotiation views.** `cw.position_current`,
  `cw.position_revival` and `cw.renewal_drift`, each `CREATE OR REPLACE` with the
  existing select list preserved exactly and a scoping expression added to its
  own WHERE. On `cw.position_revival` the expression is placed in WHERE, before
  the grouping, so the aggregate counts rows rather than being filtered after
  the counts are computed.
- **(c) Read scoping of the two concession views.** `cw.concession_state` and
  `cw.concession_in_force`, same treatment, through `cw.concession.agreement_id`.
  On `concession_in_force` the pre-existing `not exists` clause is left intact
  and the scoping ANDed onto it.

Header records, as required: the claimed number and why; the deliberately-open
administrator read boundary (no grant added, and no `administrator` branch in any
WHERE clause, because it could never execute); the `cw.open_renewal` SECURITY
DEFINER residue pointing at NC-03 with an explicit "do not rewrite it here"; the
settled U1 renewal baseline, inherited and not reopened; and the one live
consumer (`backend/doorway/reads.py`, GET /concessions) with the follow-up.
A verbatim prior-text footer quotes all four policies and all five view
definitions for a reverting migration.

## Blocker

**`governance.test.mjs` fails, and NC-01 may not fix it.** All six failures have
one cause: that suite reads `cw.concession_state` and `cw.concession_in_force` on
the database owner's connection, where `cw.app_role()` is null (settled decision
U3), so a now-scoped view correctly returns nothing. It is the same adjustment
made inside `negotiation.test.mjs` — route each such read through a role that
holds the view — at eight call sites (lines 88, 90, 159, 162, 190, 237, 289, 329).
No schema change is implied and no assertion's meaning changes.

NC-01's file rule is explicit: one new migration plus `negotiation.test.mjs`,
nothing else. `governance.test.mjs` is claimed by no package in this set, so the
edit is left undone and disclosed rather than taken quietly. **`run-all.mjs` is
therefore not green, and is not claimed to be.** This needs an owner before
NC-01 merges; it is roughly ten minutes of work.

## Deviations disclosed

1. **`run-all.mjs` is not green.** Above. The package's acceptance criterion
   assumed the five views had no owner-connection readers outside the file NC-01
   owns; one suite has eight.
2. **Five existing reads inside `negotiation.test.mjs` were re-pointed at a
   role.** The same owner-connection effect, inside the file this package owns.
   The assertions are unchanged; only the connection they run on moved, with the
   reason written beside the helper. Without this the package would have broken
   tests it owns.
3. **Two new refusal checks were tightened after they passed against the
   unscoped schema.** (a) The four write refusals originally used the suite's
   `mustNotWrite` helper, which accepts any raise; the round case then "passed"
   without the migration because the round-sequence trigger fires before the row
   policy and, seeing none of the rounds a non-owner cannot read, refuses the
   round number first. The check now asserts PostgreSQL's own `row-level
   security` refusal and uses round number one, which is the number that gets
   past the trigger. (b) The two position-view read probes originally resolved a
   view row to its agreement by joining `cw.negotiation` — and that join carried
   `cw.negotiation`'s own read policy, hiding the leak. The probes now select
   only the view's key and resolve ownership afterwards, as the owner, outside
   the role's session. Both were found by the counterfactual run, not by
   inspection.
4. **No mutation-check row added**, as the package instructs: this package adds
   no guarded Python line.
5. **`cw.open_renewal` untouched**, as instructed. It remains SECURITY DEFINER
   and still walks around the policies installed here. Flagged in the header as
   NC-03's work.
6. **No grant to `cw_administrator`** on any of the five views, and no
   `administrator` branch in any WHERE clause. The gap is stated in the header
   and left open as an owner decision.
