# NC-06 — Ladder placement and alternative ranking — implementation report

Date: 2026-07-27. Owner: NC-06 single-owner implementer. Not committed.

## What was built

A new engine module that answers two questions deterministically, with no
database and no network: where a negotiating position sits on its ladder, and
what alternatives are available from there down to the floor. It is handed rung
rows in the shape `cw.ladder_rung` already stores; it does no SQL itself.

The floor is never crossed. A position recorded below the floor comes back as a
refusal carrying the ladder's own reason, never as a low-ranked option.

- `backend/engine/test_ladder_placement.py` (NEW)

No existing file was modified.

## Public shape

- `read_ladder(category, severity, rung_rows)` — validates rows into a `Ladder`
  or returns a `Refusal`. Re-checks what the schema enforces (contiguous from 0,
  exactly one floor) because rows may arrive from a query, a fixture or a cache.
- `place(ladder, clause_ref)` — a `Placement` (rung, at_floor, rungs_to_floor)
  or a `Refusal`.
- `rank(ladder, clause_ref)` — a `Ranking`: what is above the position, and the
  retreat path from the position down to and including the floor.
- `retreat_path(ladder)` — rung 0 to the floor, for the not-yet-placed case.

Refusals are returned, not raised, and carry a stable code (`no_rungs`,
`floor_missing`, `floor_duplicated`, `rungs_not_contiguous`, `rung_duplicated`,
`not_a_rung`, `below_floor`) separate from the human sentence. Tests branch on
the code, never on the sentence.

## Deviations

1. **`engine/mutation_check.py` not touched.** NC-06's target-file list names
   only the new module and its new test module. Per the standing rule for shared
   files, the mutation harness was left alone and the omission is recorded here.
   Consequence: the new module's guarded lines are not represented in the
   mutation count. If the harness should cover it, that is a one-row follow-on
   in whichever package owns `mutation_check.py`.
2. **`npm run verify` not run.** It runs the database, doorway and mutation
   suites as well, and the working tree has uncommitted in-flight changes in
   `backend/doorway/` and `backend/db/` from other packages. A failure there
   would not be attributable to NC-06 and a pass would not be evidence about it.
   The engine suite and the engine mutation harness — the two that can speak to
   this package — were run and are green above.

## Findings to report, not to fix

- The engine already carries a `model.Ladder` used by `resolution.descend`. It
  stores `floor_rung` as a single integer, so it structurally cannot express a
  missing or duplicated floor — the damaged-ladder cases NC-06 requires be
  refused. That is why this module validates rows rather than reusing that type.
  Whether the two ladder representations should later converge is an owner
  question outside this package.
