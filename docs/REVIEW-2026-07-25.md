# Clausewerk — Comprehensive Review (2026-07-25)

A full review of the codebase and the planned architecture: the four architecture documents, all
ten decision records, the database layer, the Python engine, and the test suites. Companion
document: [`IMPROVEMENT-PROPOSAL-2026-07-25.md`](../IMPROVEMENT-PROPOSAL-2026-07-25.md), which
turns these findings into an ordered plan.

**How this review was done.** Three independent deep reviews (Python engine, database layer,
architecture documents) plus a direct read of the newest uncommitted work
(`NEGOTIATION-ARCHITECTURE.md`, ADR-0010). All test suites were run and pass: 104 Python tests,
all five database suites, and both mutation harnesses (24/24 and 15/15 mutations caught).

---

## 1. Overall verdict

**This is unusually good work — and it is good in the way that matters most: the thinking is
honest.** Decision records state their costs openly. Tests are deliberately broken to prove they
can fail. Defects found were fixed rather than documented around. The core promise — *no
machine-written words ever reach a contract* — is not a slogan; it is enforced by a character
counter that the build refuses to ship without.

The problems this review found fall into three groups, in order of importance:

1. **The newest decision (ADR-0010, letting AI draft clause candidates) is sound in substance
   but incomplete in execution.** It changes the product's central claim, and the follow-through
   — updating the older records it contradicts, deciding what goes on the document footer,
   naming who watches the new control — has not happened. It is also not yet committed to the
   repository.
2. **Several protections hold today only because nothing has attacked them yet.** The database's
   permission system, its tamper-evident log, and its "immutable" records all have specific,
   fixable holes that the current tests structurally cannot see — because the tests run as the
   database owner, in a single session. This is the same class of fault the project already
   caught once ("a protection that worked by accident is not a protection"); there are more.
3. **The two halves of the backend have never actually met.** The Python engine and the database
   are each well-tested alone, but the code that writes engine results into the database is
   already mismatched with the tables it targets, and one field is fingerprinted but never
   stored — which would quietly break the "reproducible forever" promise for some contracts.

None of these are architectural mistakes. They are the ordinary gap between a design being right
and a system being finished, caught at the right time — before any production data exists.

## 2. What is genuinely strong

Worth recording, because it should be preserved as the system grows:

- **The trust boundary is real, not rhetorical.** One narrow, checkable object (the manifest)
  crosses from AI to deterministic code. Unknown categories die at the boundary — and after a
  found defect, that check fails *closed*.
- **The claim is counted, not asserted.** `authored_characters()` checks every produced contract
  character-by-character against approved wording plus a declared structural allowlist, and a
  control test proves the counter actually looks.
- **Byte-identical reproduction is tested the hard way.** A stored contract is rebuilt after the
  library is aged three years — retirements, expiries, additions — and must come out identical;
  a second test proves today's library would give a *different* answer, so the first can't pass
  by luck.
- **Mutation testing is practiced, not preached.** 39 deliberate breaks across both stacks, each
  required to be caught by a named test. This practice has already caught three real faults.
- **The read-side integration test is a model.** `loader-sql.test.mjs` extracts the Python
  engine's SQL verbatim and runs it against the real migrated schema — spec drift between the
  two languages cannot happen silently on the read path.
- **The signed file is the contract.** Frozen bytes, fingerprinted, amendments append rather
  than edit, drift reported rather than applied, and rebuild-vs-file disagreement treated as an
  incident. This is exactly right and rarer than it should be.
- **The documents reason in public.** Every ADR carries an honest Consequences section;
  `memory.md` records corrections, including the owner's own.

## 3. Findings — the architecture and its documents

### 3.1 ADR-0010 changes the product's claim, and the surroundings haven't caught up (HIGH)

The decision itself is well-located: assembly still generates nothing; AI may only *draft
candidates* that a named lawyer approves; origin is stamped permanently on every clause. That is
a defensible position, honestly argued. What is missing:

- **The record is invisible to the project's own system.** ADR-0010 and
  `NEGOTIATION-ARCHITECTURE.md` are uncommitted; the ADR index stops at 0009; ADR-0001 (the
  founding invariant) and ADR-0002 (the "one crossing point" claim) carry no "amended by" note.
  A reader of the founding records gets a false picture. Ironically, the most consequential
  decision in the repository is the least-socialised one.
- **ADR-0002 is now wrong and unamended.** "Auditing 'can model output reach a document?' means
  reading one filter" no longer holds: model prose can now reach the deterministic side via
  Builder drafts, supplier-paper atomisation, and the review queue's AI-candidate path. The
  manifest is no longer the *sole* crossing.
- **The economics are unreconciled.** ADR-0001's founding argument was that adversarially
  reviewing generated language costs more than writing it. ADR-0010's payoff (the library grows
  faster) is only real if review is *lighter* than that standard. The design instruments the
  danger (the unedited-approval rate) but no one owns that number and no threshold exists —
  named as an open question and left there. A binding control with no owner is not a control.
- **The public claim is undecided.** "0 LLM-authored characters" stays true of assembly and
  false of the library once the first AI-drafted clause is approved. Both numbers will be
  computed; which goes on the document is explicitly an owner decision — and it should be made
  *before* the first AI-drafted clause is approved, not after.
- **A counsel question should be a gate.** Whether counterparties have any interest in knowing
  that signed wording began as an AI draft is flagged as worth asking counsel — nothing
  currently prevents the first such clause shipping before the answer exists.

### 3.2 Contradictions between documents (MEDIUM-HIGH)

- **Who descends the ladder?** The Clause Library Architecture says in §3 the matcher can settle
  a vendor ask against a fallback rung *without a human*, and in §7 that descending a rung is a
  *Requester* act, recorded. Every concession must carry a named approver — but §7 also says
  concessions are created *automatically* on resolution. If a machine descends, who is the
  approver, and why isn't it logged as a machine act (the exact thing ADR-0008 was written to
  prevent)? This ambiguity sits at the centre of the system's main scaling claim.
- **Supplier paper after signature.** The negotiation spec now supports running a deal to
  execution on the vendor's template — but such an agreement has no clause decisions behind it,
  so the lifecycle system's obligation lookup produces *nothing*, and neither document says what
  happens next. The flagship claim ("we already know exactly what we committed to") silently
  excludes the very deal class the negotiation spec just embraced.
- **Conceded vendor wording has no obligations either.** Obligations are read from clause
  records; conceded vendor text has no clause record. The obligations most likely to be missed
  are exactly the hardest-negotiated ones. Acknowledged nowhere.
- **Renewal restarts from our book.** Renewal re-assembles from standard positions, discarding
  every concession the counterparty won last time. Commercially, vendors renew from the executed
  agreement. Unaddressed.
- **The package-trade blind spot is admitted three times and mitigated zero times** (ADR-0007,
  CLA §11.5, NA §9.3) — and it now feeds the analytics: the concession record systematically
  misreads trades as unilateral giveaways, and the intelligence layer proposes library changes
  from that biased record.

### 3.3 Dangerous-to-defer open questions (MEDIUM)

- **A ladder floor can expire silently.** Expiry is invisible by design (no event, no
  notification), and the ladder-expiry interaction is an admitted open question. Result: the one
  control described as "absolute" can become undefined mid-negotiation. Decide before ladders ship.
- **Master agreement + statements of work is not modelled** — and it is the dominant structure in
  real procurement. As specified, the lifecycle system cannot represent its primary use case.
- **Legal hold does not exist.** The retention service deletes on a clock with no mechanism to
  suspend deletion for litigation — in a system whose selling point is what survives a dispute.
- **E-signature capture is one field.** The entire lifecycle rests on reliably obtaining the
  final executed bytes (counterparts, wet-ink scans, exhibits) from a signing provider; the spec
  provides an envelope reference and nothing else.
- **The audit hash-chain scheme is unspecified** yet everything provenance-shaped leans on it.

### 3.4 Documentation debt (LOW, but corrosive)

The rule grammar is cited to "CLA §4", which is actually the Concessions section — the grammar is
specified nowhere. `docs/data-model.md` predates three of the four architecture documents.
`ARCHITECTURE.md` §5 still lists four roles; ADR-0008 defines five. The ADR index's claim that
every ADR is implemented in the prototype is now false for 0008–0010. The engine README
miscounts its tests and says the document service is "not yet started" above a section describing
the built document service.

### 3.5 Over-engineering worth trimming (LOW)

The full negotiation-intelligence layer (seven signals, decay weighting, proposal queue)
presupposes a concession corpus that won't exist for years at plausible deal volume. A counting
query delivers the "14 of 17 deals" insight for a fraction of the build. Entitlement valuation
depends on integrations that are themselves undefined. Decision records retain full copies of
suppressed candidates; the spec itself notes storing IDs would do — that mitigation should
simply be adopted.

## 4. Findings — the database layer

The schema's ideas are sound (identity/content split, computed validity, stored snapshots,
frozen signed bytes). The holes are in enforcement, and share one root cause: **the tests run as
the database owner in a single session, and the owner bypasses row-level security.**

| # | Finding | Severity |
|---|---|---|
| D1 | **Concession promotion breaks under real permissions.** `promote_concession()` ends with an UPDATE on a table that has no UPDATE policy. Run as a real `legal_admin` role (not the owner), the update silently does nothing — the function reports success, the "cannot promote twice" guard is defeated, and the same vendor text can be minted into the library repeatedly. | HIGH |
| D2 | **The tamper-evident log corrupts itself under normal concurrent use.** The hash chain reads "the previous hash" without any lock; two simultaneous writes fork the chain, and the verifier then reports *tampering* on an honest database. Any multi-user deployment hits this in week one. Separately, deleting the newest entries is undetectable — the chain has no anchored tail. | HIGH |
| D3 | **Identity is self-asserted.** The role and actor the policies trust come from session variables any connected client can set. Attribution in the audit log is spoofable, and several read policies are bypassable by any role that can execute SQL. Survivable only if the connection layer is fully trusted — and the stated deployment target (pooled connections) leaks these variables across clients. | HIGH |
| D4 | **"Immutable" records have editable holes, and edits leave no audit trace.** On approved clauses: the named reviewer can be rewritten, and a retired clause can be silently *un*-retired (the audit hook only fires in the retire direction). On conflict rules: the effective date can be moved retroactively, rewriting which rules were in force historically. | HIGH |
| D5 | **The "absolute" floor consults the wrong ladder.** The below-floor check picks a floor with no severity filter and no ordering — a category with both Standard and High ladders yields an arbitrary floor, so a High-severity concession can slip past the stricter floor. Concessions also don't record which ladder they descended, and rungs are editable, so historical rung references decay. | HIGH |
| D6 | Concessions are spec'd immutable but aren't (no update-blocking trigger; a full-row UPDATE grant exists; updates are unaudited). Currently protected *by accident* — by the missing policy that is bug D1. | MEDIUM |
| D7 | An agreement's status can never change (no UPDATE path), so every signed deal remains "negotiating" forever, and nothing ties agreement status to the executed record. | MEDIUM |
| D8 | Claimed coherences unenforced: clause-ID prefix vs category short-code; rung clause severity vs ladder severity (test data itself violates this); run-store rows lack the CHECK constraints used everywhere else. | MEDIUM |
| D9 | Missing indexes on common lookups; TRUNCATE not covered by the immutability story; silent-no-op DELETE hides application bugs. | LOW |

**Missing entirely:** the Review queue — the architecture's single mutation gate — has no
tables: no ticket, no pending→verified/rejected state machine, no rejection note, nowhere for
ADR-0010's draft provenance to land. `promote_concession()` is one path through a gate that
otherwise doesn't exist yet. Also absent (acknowledged): obligations, sessions/transcripts,
per-inference-call logging, retention marking.

## 5. Findings — the Python engine

Interior logic is solid; the faults cluster at the edges.

| # | Finding | Severity |
|---|---|---|
| E1 | **Ladder condition is fingerprinted but never stored.** The snapshot hash includes each ladder's status, but the run store has no column for it and rebuild hard-codes "intact". Any run whose snapshot held a degraded ladder can never be reproduced — the fingerprint will never match — and a replayed descent would descend a ladder that escalated at run time. All test fixtures use intact ladders, so nothing sees it. | HIGH |
| E2 | **The write side of the engine↔database seam has never been exercised and is already wrong.** Engine output labels a column `category` holding the human label; the target table wants `category_key` holding the key. The read side has a superb cross-language test; the write side has none — two green suites, one broken seam. | HIGH |
| E3 | **When two versions of the same clause are both selectable, resolution picks the *oldest*.** Deterministic, but almost certainly the wrong contract position, and untested. Ladders declare a preferred rung; resolution never consults ladders at all. | HIGH |
| E4 | **A lapsed boilerplate clause vanishes silently.** If an always-include clause (Definitions, Order of Precedence…) expires, contracts simply lose the section — no decision record, no warning — while the risk pass carefully distinguishes "lapsed" from "never existed". | MEDIUM |
| E5 | **Real-world Word documents will lose text.** Redline parsing reads only direct children of a paragraph; text inside hyperlinks, content controls, and smart tags vanishes from what a Review ticket shows Legal. Tracked *moves* are unhandled. All fixtures are hand-built minimal XML. | MEDIUM |
| E6 | **Hostile uploads are unmitigated.** The vendor-document parser (the module's own docstring: "the one place untrusted bytes enter the system") has no protection against entity-expansion attacks or zip bombs. | MEDIUM |
| E7 | **The manifest trust boundary exists only in the prototype.** No backend code drops unknown categories or coerces severity — a hallucinated category flows through and is misdiagnosed as a library coverage gap, corrupting the one report the system prizes. | MEDIUM |
| E8 | Small items: a misnamed and dead `at_floor` property; dead code and imports; README drift; a substring-match test that asserts nothing. | LOW |

## 6. Where the risk concentrates — one paragraph

Every HIGH finding above shares a shape: **a guarantee the documents state absolutely, enforced
by a mechanism with a specific hole that current testing cannot reach.** The project already
discovered this pattern once and wrote it down ("a protection that worked by accident is not a
protection"). The remedy is the same one the project already believes in: test as the real
roles, not the owner; exercise the seams, not just the sides; and put the mutation harness on
the protections that matter most. The Improvement Proposal orders exactly that work.
