## Cycle 1 — Ambiguous request length

- **Observed:** the HTTP transport read one `Content-Length` value even when a
  request carried the header more than once. Different HTTP hops may select or
  combine those values differently, making the request boundary ambiguous.
- **Plan:** centralize length parsing and reject every duplicate before reading
  any bytes.
- **Implemented:** both JSON and document uploads now use the shared,
  fail-closed parser.
- **Validation:** `test_duplicate_content_lengths_are_refused_as_ambiguous`
  reproduces the conflicting-header request and proves it is refused unread.
