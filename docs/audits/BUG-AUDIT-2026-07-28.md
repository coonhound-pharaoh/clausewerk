# Bug and Security Audit — 2026-07-28

This ledger records ten fresh audit cycles begun from commit `710cb49`. Each
entry states the observed defect, the bounded fix, and the evidence used before
delivery.

## Cycle 1 — Ambiguous request length

- **Observed:** the HTTP transport read one `Content-Length` value even when a
  request carried the header more than once. Different HTTP hops may select or
  combine those values differently, making the request boundary ambiguous.
- **Plan:** centralize length parsing and reject every duplicate before reading
  any bytes.
- **Implemented:** both JSON and document uploads now use the shared,
  fail-closed parser.
- **Validation:** `test_duplicate_content_lengths_are_refused_as_ambiguous`
  reproduces the conflicting-header request and proves it is refused unread.

## Cycle 2 — Non-standard request-length spellings

- **Observed:** Python's integer parser accepts spellings such as `+2` and
  non-ASCII digits that HTTP's `Content-Length` grammar does not. Another hop
  can reject or interpret those spellings differently.
- **Plan:** accept only one or more ASCII decimal digits.
- **Implemented:** length parsing now checks the wire grammar before conversion.
- **Validation:** the focused test proves signed, padded, and non-ASCII lengths
  are refused before their bodies are read.

## Cycle 3 — Ambiguous bearer identity

- **Observed:** duplicate `Authorization` fields caused the server to select the
  first credential. A proxy or gateway can select a different field, making the
  authenticated identity hop-dependent.
- **Plan:** accept exactly one authorization field and otherwise present no
  credential to the application.
- **Implemented:** `_token()` now fails closed for missing or duplicate fields.
- **Validation:** the regression test presents attacker and victim bearer
  values together and proves neither is selected.

## Cycle 4 — Wildcard access to the local development identity seam

- **Observed:** without configuration, every response granted cross-origin read
  access to every website. The development sign-in has no password, so an
  unrelated site could name a known demo account, receive its own bearer token,
  and read that account's records from localhost.
- **Plan:** make cross-origin API access opt-in while retaining the explicit
  `CW_ORIGIN` development escape hatch.
- **Implemented:** the default response omits
  `Access-Control-Allow-Origin`; a configured origin is still emitted.
- **Validation:** focused tests prove the default grants no origin and an
  explicit development origin still works.

## Cycle 5 — Ambiguous document selector

- **Observed:** `GET /runs/contract` silently selected the first of repeated
  `run` parameters. Other HTTP components and client libraries can select the
  last, making the document named by one request ambiguous.
- **Plan:** recognize repeated supported selectors and fail closed before the
  application or database sees one.
- **Implemented:** query parsing now returns a 400 for repeated `run` values.
- **Validation:** the focused regression test presents two run IDs and proves
  neither reaches the application.

## Cycle 6 — Pathological length crashes the parser

- **Observed:** a `Content-Length` containing thousands of digits passes the
  digit grammar, then Python's integer-conversion safety limit raises an
  uncaught exception. An invalid request is therefore reported as a service
  failure.
- **Plan:** bound the length token before integer conversion.
- **Implemented:** values beyond 20 decimal digits are refused unread as a
  malformed request.
- **Validation:** the regression test submits 5,000 digits and proves the
  parser returns 400 without raising.

## Cycle 7 — Unbounded query-field parsing

- **Observed:** the server parsed every query field before discarding unsupported
  names, with no field-count ceiling. A request could spend memory and CPU on an
  arbitrary number of values that the application never uses.
- **Plan:** put a small transport-level ceiling above the one supported selector
  and convert parser overflow into a caller error.
- **Implemented:** query parsing is capped at 20 fields and returns 400 when the
  cap is exceeded.
- **Validation:** the regression test sends 100 ignored fields and proves the
  request is bounded and refused.

## Cycle 8 — Malformed URL escapes accepted as file names

- **Observed:** invalid percent escapes such as `%ZZ` survived URL decoding and
  were treated as literal static-path characters. Upstream components may reject
  or normalize the same target, creating inconsistent routing decisions.
- **Plan:** validate every percent marker before decoding or touching the file
  system.
- **Implemented:** malformed escapes now produce a 400 response.
- **Validation:** the focused test proves `%ZZ` is refused rather than converted
  into a relative file name.

## Cycle 9 — Invalid UTF-8 aliases a replacement-character path

- **Observed:** URL decoding used replacement mode, so invalid bytes such as
  `%FF` became the Unicode replacement character. Distinct invalid request
  targets could therefore collapse onto an unintended on-disk file name.
- **Plan:** decode static paths as strict UTF-8 and refuse undecodable bytes.
- **Implemented:** Unicode decode failures now return 400 before path
  resolution.
- **Validation:** the regression test proves `%FF.js` never becomes a file-system
  path.
